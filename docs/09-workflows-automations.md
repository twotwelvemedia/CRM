# Automations

Build most of these under Plutio's Automations builder: a **trigger** (an event in Plutio — a proposal signed, an invoice overdue, a task marked complete) paired with one or more **actions** (create an invoice, send a message, create a task, update a project, send a notification) — actions can chain from a single trigger. Email bodies referenced are in `templates/emails/`. Automation #2 is now built natively in SuiteDash (see below) — Zapier is no longer part of this system.

| # | Trigger | Action(s) | Notes |
|---|---|---|---|
| 1 | A new Project is created (Plutio-native automation, "when a project is created" → "all projects") | Create a "Kickoff call" task (assignee: Project Owner) on the triggering project | Originally designed around "Won + Deposit Paid," but contracts and deposits aren't consistent across every job (some have neither) — no single upstream event reliably signals "this job is starting" the way a card landing on a specific column would. Project creation itself is the one universal, always-true moment, so that's the trigger instead. The actual decision ("is this job a go, and which template matches it") stays a manual call the Producer makes when they click Start from Template — same category of judgment call no automation could make reliably anyway. **Welcome email isn't a custom automation step at all** — Plutio sends its own invite email automatically the moment the Producer adds the Client as a project member, so just make sure that happens right after creating the project. The new kickoff task lands ungrouped (no Task Group assignment, since the first Task Group's name differs between templates — e.g. Podcast starts with "Show Setup," not "Onboarding & Kickoff") — one quick manual drag into the right column, confirmed via live test. |
| 2 | New Inquiry Kickoff Form submitted on the website (native SuiteDash form, instant — no webhook, no third-party service) | SuiteDash creates/updates the CRM Contact (+ Company) as a **Lead**, writes the submitted project details to the Project custom fields, logs the message as a CRM Note → sends an email notification to Marcus Williams (info@two-twelvemedia.com) with the full submission (`{{allSubmittedFormData}}`) | Built and live — see docs/06, Form 1 ("New Inquiry", `https://app.suitedash.com/frm/u/24Xey5xetrdCwVGur`). This replaced the original Plutio-era Zapier/custom-HTML design: SuiteDash's Kickoff Form type natively handles both the Contact/Company creation and the notification, configured directly in the form builder's "Assignments & Automations" section — no external service needed. Sales still adds the actual Sales Pipeline card to "New Lead" by hand from the notification email, same manual handoff as before. No duplicate-email dedup; merge duplicate Contacts manually if that comes up. |
| 3 | Task "Review link sent" is marked complete (Task Group 5) | Send "Review Ready" email (`review-request-email.md`) with the client's portal link → create follow-up task "Check for feedback" due in 3 days | |
| 4 | Invoice becomes overdue | Day 0 and Day 7: send reminder email (`invoice-reminder-email.md`); Day 14: apply late fee + notify Producer | See docs/08 for the late fee policy this implements |
| 5 | Task "Final files delivered" is marked complete (Task Group 6) | Send Final Invoice if not already sent → create task "Send testimonial request in 3 days" | |
| 6 | Task "Send testimonial request" comes due | Send testimonial email (`testimonial-request-email.md`) with link to Form 5 | |
| 7 | Sales Pipeline card marked "Lost" | Set the Lost Reason field → create task "90-day follow-up" assigned to Sales | Keeps lost leads in a nurture cycle instead of disappearing |
| 8 | Podcast Subscription bills for the month | Create a new Episode Task Group from the Podcast template | Skip this for Podcast clients billed per-episode instead — they get a manual step each time an episode publishes |
| 9 | All tasks under a Task Group are marked complete | Add a final "Phase complete — notify client" task as the last item in each group, or trigger off group completion if the Automations builder supports it | Confirm whether "all tasks in a group complete" is an available trigger once you're actually in Automations — if not, the last-task-in-group convention is the fallback |
| 10 | Discovery Call booking confirmed via Scheduler | Create task "Prep for discovery call" assigned to Sales, due 1 hour before the meeting → notify Sales | Scheduler handles the client-facing confirmation/reminders automatically (docs/13) — this automation is just for your own prep |
