# Automations

**Correction from earlier (Plutio-era) planning:** there's no single global "Automations builder" in SuiteDash the way Plutio had one. Automations are configured per-object instead — on a Task Template's individual task (row ⋮ → **Manage Automations** → **Configure Automations**), or on an Invoice Generator/Subscription (its own **Assign Automations** section, e.g. "Invoice is Paid" / "Invoice is Past Due"). Each one still pairs a **trigger** (this task's completion requirement is met, this invoice is paid, etc.) with one or more **actions**, picked from a shared action library (Send Email to Target, Create Task, On-Demand/Recurring/Accumulating Invoice Generator, Apply Task Template, and more). Email bodies referenced are in `templates/emails/`.

**Automation #1 detail:** originally designed around "Won + Deposit Paid," but contracts and deposits aren't consistent across every job (some have neither) — no single upstream event reliably signals "this job is starting" the way a card landing on a specific column would. Project creation itself is the one universal, always-true moment, so that's the trigger instead. The actual decision ("is this job a go, and which template matches it") stays a manual call the Producer makes when they click Start from Template — same category of judgment call no automation could make reliably anyway. The new kickoff task lands ungrouped (no Task Group assignment, since the first Task Group's name differs between templates — e.g. Podcast starts with "Show Setup," not "Onboarding & Kickoff") — one quick manual drag into the right column.
